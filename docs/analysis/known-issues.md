# مشکلات شناخته‌شده

Last Updated: 2026-07-15

## مشکلات فنی

| مشکل | اثر | پیشنهاد |
|---|---|---|
| `ddl-auto=update` | تغییر کنترل‌نشده schema | مهاجرت به Flyway/Liquibase |
| SQLite در توسعه اصلی | ناسازگاری احتمالی با تولید | افزودن profile PostgreSQL |
| lazy loading در responseها | خطای serialization | استفاده کامل از DTO و fetch plan |
| secret در `application.yaml` | ریسک امنیتی | rotation و انتقال به environment |
| fake endpointهای callback | امکان سوءاستفاده در تولید | dev profile، امضا یا token داخلی |

## مشکلات امنیتی

| مشکل | توضیح |
|---|---|
| احتمال public بودن برخی endpointهای گزارش | باید مجوزها بازبینی شوند |
| سرویس‌اکانت Keycloak حساس است | باید least privilege داشته باشد |
| sync کاربر نیازمند کنترل audit است | ایجاد/ویرایش کاربر باید قابل ردیابی باشد |

## مشکلات فرانت‌اند

| مشکل | اثر |
|---|---|
| ترکیب inline style و CSS | نگهداری سخت‌تر |
| نبود تست UI | regression در طراحی‌ها دیر دیده می‌شود |
| وابستگی به permission frontend | backend باید همچنان منبع تصمیم امنیتی بماند |
| date picker شمسی | نیازمند تست کامل در همه فرم‌ها |

## مشکلات فرایندی

| مشکل | اثر |
|---|---|
| تغییر BPMN روی instanceهای فعال | احتمال ناسازگاری متغیرها |
| task بعدی در delegation | در گذشته خطای `NEXT_DELEGATION_TASK_NOT_FOUND` رخ داده است |
| متغیرهای سازمانی ناقص | task برای کاربر مرتبط دیده نمی‌شود |
| ruleهای ابلاغ | نیازمند تایید دقیق کسب‌وکار |

## مشکلات داده‌ای

- بعضی داده‌های قدیمی ممکن است شناسه یا نام سازمانی کامل نداشته باشند.
- اطلاعات آدرس و postal code باید از `ContactInfo` به شکل پایدار استخراج شود.
- تاریخ ابلاغ باید با date+time واقعی callback ذخیره شود، نه offset ثابت.
