# پیاده‌سازی مدل برگ اجرایی سنیم

شاخه: `feat/sanim-execution-document-model`

## تغییرات

| بخش | پیاده‌سازی |
|---|---|
| دریافت | `announcementType` اجباری؛ پنج قالب `LTR_EF03`، `LTR_EF23`، `LTR_EF23_1`، `LTR_EF23_2`، `LTR_EF104` |
| XML | متن کامل دریافتی، بدون بازنویسی، در `DebtPaperPushRecord.xmlPayload`؛ جزئیات مالی جدول/ستون جدا ندارند |
| سند اولیه | `FinalizedDebtPaper.sourceDocument` شامل اطلاعات اصلی مؤدی، سند، مستند صدور، اداره، مبنای مبلغ و هفت مبلغ اولیه |
| مبالغ جاری | `DebtInformation.currentAmounts`؛ نسخه مستقل از مبالغ اولیه |
| استعلام | پاسخ و مبالغ استخراج‌شده در `DebtInquiryResult`؛ تغییر مبالغ جاری و ثبت تاریخچه در یک تراکنش |
| کد اداره | `sourceTaxOfficeCode` از نوع متن؛ مستقل از کلید داخلی و با حفظ صفرهای ابتدای کد |
| دقت | `BigDecimal` در Java؛ ستون‌های مستقل `TEXT` با مبدل دقیق در SQLite؛ مقادیر منفی و اعشاری حفظ می‌شوند |
| API و نمایش | هفت مبلغ جدید به شکل رشته اعشاری ارسال می‌شوند؛ صفحه جزئیات و چاپ، مبالغ اولیه و جاری را بدون تبدیل به `Number` نشان می‌دهند |
| جست‌وجو | مرزهای مبلغ با `BigDecimal` مقایسه می‌شوند؛ مقایسه قبل از صفحه‌بندی صورت می‌گیرد |
| سازگاری | روابط پرونده، اشخاص، تاریخچه و ساختار سازمانی حفظ شده‌اند؛ ستون‌های مالی قدیمی حذف نشده‌اند |

هفت ستون مالی در هر مجموعه: `outstandingDebtAmount`، `totalTaxAmount`، `totalDutyAmount`، `totalPenaltyAmount`، `totalPaidAmount`، `totalCreditAmount`، `totalRemissionAmount`.

جزئیات فرمول‌ها: [گزارش فرمول‌ها](sanim-aggregate-formulas-report.fa.html).
نسخه نگاشت اولیه: `sanim-2026-09-v1`.

## رفتار دریافت و گردش‌کار

- XML پیش از نگاشت در تراکنش مستقل ثبت می‌شود؛ شکست نگاشت یا قواعد صدور، رسید را حذف نمی‌کند.
- تعارض یا نقص هویت/مبلغ → `NEEDS_REVIEW` و پاسخ خطا؛ پرونده قابل پردازش ساخته نمی‌شود.
- `reference` تکراری حتی با محتوای یکسان → HTTP 409.
- تکرار جزئیات نمایشی پذیرفته می‌شود؛ تگ مصرف‌شده در تجمیع اگر مبهم باشد، انتخاب اولین/آخرین انجام نمی‌شود.
- سند معتبر بدون واحد داخلی ذخیره می‌شود و شناسه پرونده برمی‌گردد؛ وضعیت رسید `WAITING_ORGANIZATION` است و گردش‌کار شروع نمی‌شود. گردش‌کار فعلی هنوز ارجاع سازمانی داخلی می‌خواهد؛ کد سنیم خودکار به شناسه داخلی تبدیل نمی‌شود. مسیر تعیین ارجاع و ازسرگیری این اسناد در این تغییر اضافه نشده است.
- شرح «دلیل صدور» در سند اولیه ذخیره می‌شود؛ جایگزین «علت قطعیت» قدیمی نشده است.
- قاعده مالی قدیمی که تفکیک ناموجود جرایم قابل‌بخشش/غیرقابل‌بخشش می‌خواهد، برای سند سنیم خطا می‌دهد؛ باید به ویژگی تجمیعی معتبر نگاشت شود.

## قرارداد مبالغ و استعلام

- نبود تگ مالی در XML اولیه فعلاً صفر است؛ تگ خالی، غیرعددی یا مبهم صفر محسوب نمی‌شود.
- مانده EF03 از `HB` است؛ EF23_2 مالیات خالص گزارش‌شده دارد؛ بخشودگی EF03 ترکیب معافیت و بخشودگی است.
- نگاشت پیشنهادی EF104: شماره/تاریخ سند `F/G` و مستند مبنا `O/P`؛ ابهام معنایی مستند اصلی همچنان نیازمند تأیید کارفرماست.
- `taxAmount` پوشش پیام، اگر ارسال شود، فعلاً با `totalTaxAmount` استخراج‌شده مقایسه می‌شود. این مبنا فرض قراردادی است، نه فرمول مصوب؛ اگر منظور فرستنده مجموع بدهی باشد، قرارداد و این مقایسه باید اصلاح شوند. اختلاف به بررسی ارجاع می‌شود و هیچ مقدار خامی از دست نمی‌رود.
- برای استعلام، شیء اختیاری `amounts` همین هفت ویژگی را می‌پذیرد؛ ویژگی غایب یا null در پاسخ جزئی مقدار قبلی را تغییر نمی‌دهد. صفر صریح، صفر اعمال می‌کند.
- پاسخ قدیمی استعلام فقط چهار مبلغ قابل نگاشت خود را به‌روزرسانی می‌کند؛ `totalDebtRials` معادل مالیات فرض نشده و مالیات، عوارض و بخشودگی اولیه صفر نمی‌شوند.
- معیار فعلی ترتیب استعلام‌ها `lastActivityAt` است. پاسخ تکراری دوباره اعمال نمی‌شود؛ پاسخ قدیمی‌تر یا هم‌زمان، مقادیر جدیدتر را بازنویسی نمی‌کند. پاسخ بدون زمان مؤثر برای سند دارای مبالغ جاری فقط در تاریخچه می‌ماند.
- `@Version` روی اطلاعات جاری، از بازنویسی هم‌زمان بدون تشخیص تعارض جلوگیری می‌کند.

## مهاجرت

مهاجرت افزایشی و تکرارپذیر در `SqliteLegacySchemaMigrator` اجرا می‌شود؛ ستون جدید اضافه می‌کند و داده‌های موجود را حذف یا از روی مبالغ قدیمی حدس‌زنی نمی‌کند. مبالغ/مشخصات جدید اسناد قدیمی null می‌مانند؛ بازپردازش تاریخی خودکار انجام نشده است. ستون قدیمی `tax_office_id` فقط برای سازگاری باقی است؛ مرجع دقیق کد خارجی، ستون متنی جدید است.

پایگاه داده عملیاتی در این کار تغییر داده نشده است. هنگام اجرای نسخه جدید، مهاجرت روی پایگاه داده تنظیم‌شده برنامه اجرا خواهد شد؛ پیش از ارتقا نسخه پشتیبان تهیه شود.

```sh

  -DargLine=-javaagent:/home/mohammad/.m2/repository/org/mockito/mockito-core/5.17.0/mockito-core-5.17.0.jar
```
