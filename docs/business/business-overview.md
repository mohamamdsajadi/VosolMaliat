## خلاصه اجرایی

سامانه وصول مالیات برای مدیریت چرخه صدور و پردازش برگ اجرا طراحی شده است. سیستم پس از دریافت برگ بدهی قطعی، امکان ارزیابی قوانین، صدور برگ اجرا، ارجاع سازمانی از رئیس اداره کل تا کارشناس مالیاتی، ابلاغ آزمایشی از طریق «سامانه ابلاغ الکترونیک»، ارسال نتیجه به «سنیم آزمایشی»، مشاهده جزئیات، چاپ، تاریخچه و گزارش را فراهم می‌کند.

## مسئله کسب‌وکار

فرایند وصول مالیات نیازمند کنترل‌های زیر است:

| نیاز | توضیح |
|---|---|
| صدور کنترل‌شده | برگ اجرا فقط در صورت عبور از قوانین قابل صدور است. |
| تفکیک مسئولیت | هر نقش فقط در محدوده سازمانی خود وظیفه می‌بیند. |
| ردیابی | عملیات کارتابل، ابلاغ و وضعیت‌ها باید قابل ردیابی باشند. |
| مدیریت سازمانی | اداره کل، اداره مالیات و واحد مالیاتی باید قابل مدیریت باشند. |

## اهداف

- یکپارچه‌سازی صدور برگ اجرا با گردش‌کار Camunda 8.
- پیاده‌سازی کارتابل شخصی برای کاربران غیرادمین.
- اعمال نقش‌ها و مجوزهای کسب‌وکاری.
- اعمال محدوده سازمانی در مشاهده و ارجاع.
- فراهم کردن پنل مدیریتی برای کاربران، مجوزها، سازمان و قوانین.
- آماده‌سازی برای اتصال واقعی Keycloak، سامانه ابلاغ و سنیم.

## محدوده

| حوزه | وضعیت | شواهد |
|---|---|---|
| دریافت/ارسال برگ بدهی قطعی | پیاده‌سازی‌شده | `AdminDataEntryController`, `IssuanceController` |
| Rule engine صدور | پیاده‌سازی‌شده | `RuleEngineService`, `ExecutionPaperRejectionRule` |
| Rule engine ابلاغ | پیاده‌سازی‌شده | `InformRuleEngineService`, `ExecutionPaperInformRejectionRule` |
| کارتابل | پیاده‌سازی‌شده | `CartableController`, `CartableService` |
| ابلاغ و سنیم واقعی | پیاده‌سازی نشده؛ fake service دارد | `FakeElectronicNotificationService`, `FakeSanimInformService` |
| گزارش مدیریتی | بخشی پیاده‌سازی‌شده | `DashboardService`, `/api/v1/dashboard/stats` |

## ذی‌نفعان و کاربران

| گروه | نقش |
|---|---|
| ADMIN | مدیریت کاربران، مجوزها، سازمان‌ها، قوانین و مشاهده مدیریتی |
| GENERAL_OFFICE_HEAD | دریافت برگ اجرا در سطح اداره کل و ارجاع به رئیس اداره مالیات |
| TAX_OFFICE_HEAD | ارجاع به رئیس واحد مالیاتی |
| TAX_UNIT_HEAD | ارجاع به کارشناس مالیاتی |
| TAX_EXPERT | رسیدگی عملیاتی به برگ اجرا |

## قابلیت‌ها

| قابلیت | وضعیت |
|---|---|
| ورود با Keycloak/OIDC | پیاده‌سازی‌شده |
| مدیریت پروفایل محلی کاربر | پیاده‌سازی‌شده |
| sync اختیاری کاربران به Keycloak | پیاده‌سازی‌شده، نیازمند تنظیم client |
| مدیریت مجوز گروه/نقش | پیاده‌سازی‌شده |
| مدیریت واحدهای سازمانی | پیاده‌سازی‌شده |
| جستجو و فیلتر برگ اجرا | پیاده‌سازی‌شده |
| چاپ برگ اجرا | پیاده‌سازی‌شده در frontend |
| عملیات ابلاغ واقعی | برنامه‌ریزی‌شده |

## موجودیت‌ها

موجودیت‌های اصلی شامل `ExecutionPaper`, `FinalizedDebtPaper`, `Taxpayer`, `NaturalPerson`, `LegalPerson`, `DebtInformation`, `GeneralDirectorateOfTaxAffairs`, `TaxAffairsOffice`, `TaxUnit`, `AppUserProfile`, `Permission`, `GroupPermission`, `AuditLog` و موجودیت‌های fake integration هستند. شرح فنی در [پایگاه داده](../technical/database.md) آمده است.

## وضعیت پیاده‌سازی

پیاده‌سازی در مرحله فعال توسعه قرار دارد. مسیر اصلی صدور، کارتابل، ابلاغ آزمایشی و مدیریت سازمان موجود است، اما پایش تولیدی، migration رسمی، تست جامع، hardening امنیتی و اتصال واقعی به سامانه‌های بیرونی کامل نیست.

## خارج از محدوده

- احراز هویت محلی با رمز عبور در Spring.
- نگهداری password در پایگاه داده برنامه.
- TaskService مربوط به Camunda 7.
- اتصال واقعی ابلاغ/سنیم تا زمان ارائه API واقعی.
